# Critère *Modélisation des données*

## Objectif

Est-ce que la modélisation des données permet de maintenir et de faire évoluer facilement le logiciel ?

## Actions

- Identifier la modélisation des données retenue (schéma, structure, modèles). 
- Évaluer la clarté et la documentation du modèle de données. 
- Vérifier la correspondance entre le modèle de données et les besoins métier. 
- Évaluer la facilité à faire évoluer le modèle (ajout, modification, suppression de champs ou d'entités) sans casser le reste du logiciel. 
- Vérifier l'absence de redondances, d'incohérences ou de rigidités dans le modèle. 
- Mesurer automatiquement la complexité et la qualité du modèle de données. 

## Notation
Note entre 0 et 20 selon la qualité de la modélisation des données :
- 0 : modèle de données confus, non documenté ou incohérent avec le métier. 
- +5 : modèle de données identifié, clair et documenté. 
- +5 : modèle cohérent avec les besoins métier. 
- +5 : évolutions du modèle possibles sans impact majeur sur le reste du logiciel. 
- +5 : modèle exempt de redondances et de rigidités nuisibles.
