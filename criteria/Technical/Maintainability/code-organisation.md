# Critère *Organisation du code*

## Objectif

Est-ce que le code est correctement organisé et facilement analysable ?

## Actions

- Analyser l'arborescence des fichiers du projet. 
- Vérifier la cohérence et la lisibilité des noms de fichiers et de dossiers. 
- Évaluer la qualité des noms de variables et de fonctions :
  - Lisibilité des noms. 
  - Cohérence des conventions de nommage. 
- Regrouper les fonctions liées au sein de fichiers ou composants cohérents. 
- Vérifier la présence de séparations claires (par exemple code source / tests / documentation / ressources). 
- Mesurer automatiquement l'organisation du code (analyse statique de l'arborescence et des noms). 

## Notation
Note entre 0 et 20 selon la qualité de l'organisation :
- 0 : organisation confuse, noms illisibles ou incohérents. 
- +5 : arborescence claire et cohérente. 
- +5 : noms de variables, de fonctions et de fichiers lisibles. 
- +5 : conventions de nommage respectées de façon homogène. 
- +5 : regroupement logique des fonctions et séparations claires dans le dépôt.
